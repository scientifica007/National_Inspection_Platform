# Lifecycle Semantics

## الهدف

إزالة الغموض بين الحفظ والإرسال والتثبيت والاعتماد والنشر.

هذه الأفعال ليست مترادفات.

## SAVE

يحفظ Draft.

- mutable
- deletable ضمن الصلاحية
- غير نهائي
- لا يخلق حقيقة مهنية مثبتة

## SUBMIT

ينقل المسودة إلى مسار مراجعة أو استقبال طرف آخر.

- لا يعني بالضرورة التثبيت النهائي
- يحتفظ بالمؤلف والمالك
- قد يسمح بالسحب إذا كانت سياسة الكيان تسمح بذلك
- لا يستخدم كبديل غامض لـFINALIZE

## FINALIZE

يثبت المحتوى الذي يملك صاحبه سلطة تثبيته.

بعده:

- الأصل immutable
- لا destructive update
- لا delete
- أي تصحيح لاحق يتم بـAmendment/Addendum
- actor + timestamp + version/hash/audit metadata محفوظة

## APPROVE

قرار سلطة مخولة بشأن محتوى أو اقتراح أو إصدار.

- لا يغيّر مؤلف المحتوى الأصلي
- قد يغيّر status أو scope أو eligibility للنشر
- الرفض كذلك سجل قرار، لا حذف للأصل عند الحاجة إلى حفظ مسار الاعتماد

## PUBLISH

يجعل إصدارًا معتمدًا أو مسموحًا مرئيًا/قابلًا للاستعمال ضمن Scope معين.

النشر لا يساوي الملكية ولا التأليف.

## ARCHIVE

يوقف الاستعمال النشط من دون محو التاريخ.

## AMEND

ينشئ سجلًا جديدًا يصحح/يكمل سجلًا مثبتًا.

يجب أن يحمل:
- target
- author
- reason
- timestamp
- change
- supporting evidence optional

## DELETE

مسموح افتراضيًا فقط لما هو Draft/Local وغير مثبت، وضمن ملكية وصلاحية واضحة.

## قاعدة مهمة

ليست كل الكيانات ملزمة بكل الحالات السابقة.  
كل Module يختار subset صريحًا من هذه semantics، ولا يخترع معنى جديدًا للأفعال نفسها.
